# 0002 -- the fail-closed door: the door-coherence invariant + duplicate-name policy

Status: accepted (v0.1.2). Context: v0.1.0 shipped a porous construction door.
Law #2 ("fail closed at the door, then read without checking") was broken six
ways (BR-01..BR-06): the door validated a value's RANGE but not its COHERENCE
(integer-ness, base-within-buffer, name uniqueness, argument shape), and two
seams (`bytes()`, the cooperation constructors) had no coded door at all. S2
makes law #2 true with cold-path guards ONLY -- the numeric read hot path
(`getF64..getU8`, `get`) is byte-identical to v0.1.0.

## The door-coherence invariant (enforced once, at construction)

The constructor now enforces exactly this invariant, and the harness's
`checkCoherence(source, options)` evidence function encodes the same one -- the
two agree cell-for-cell across the T2 door matrix. It is O(fields) to check and
runs exactly once per reader, so it costs the read hot path nothing.

```
0 <= base                        AND base <= buffer.byteLength           (BR-01, BR-03)
count is a non-negative integer  AND base + count*stride <= byteLength   (BR-01)
for every field f:
    Number.isInteger(type[f]) AND 0 <= type[f] < 8                       (BR-02)
    Number.isInteger(offset[f]) AND offset[f] >= 0
    offset[f] + TYPE_BYTES[type[f]] <= stride                            (BR-02 stride derivation)
    name[f] is unique across the schema                                  (BR-04)
```

`base` resolves against the RESOLVED `buffer.byteLength` (post-copy for a
partial/offset view, post-unwrap for a full-span view), NOT `source.byteLength`,
so the check is coherent for the copied-window case.

## The coercion rule (BR-07)

Only a FULL-SPAN zero-offset view unwraps zero-copy: the constructor keeps
`source.buffer` as-is only when `source.byteOffset === 0 AND source.byteLength ===
source.buffer.byteLength`. ANY other view is copied to its own window of exactly
`source.byteLength` bytes:

- a nonzero-offset (pooled) view -- so surrounding pool bytes are unreachable
  (the original D7 case);
- a zero-offset PARTIAL view (`byteLength < buffer.byteLength`, e.g.
  `new Uint8Array(buf16, 0, 8)` or `arr.subarray(0, 8)`) -- BR-07.

Root cause of BR-07: the old guard was `source.byteOffset === 0` alone, which
unwrapped ANY zero-offset view to its FULL underlying buffer. A zero-offset
partial view then let the reader derive/accept a count over the full buffer and
read bytes the view does not own (an 8-byte view over a 16-byte buffer derived
count 2; `getF64(1, 0)` returned poison from beyond the window; an explicit
`count: 2` was accepted). This is the same fail-open class as BR-01: a length
resolved against bytes the caller does not own. Fix: gate the zero-copy unwrap on
FULL SPAN and route a zero-offset partial view down the existing copy branch. The
RESOLVED buffer is therefore always exactly the bytes the caller owns, so the
door-coherence invariant (which resolves length from that buffer) can never admit
a read past the view's window. The harness `checkCoherence` already bounds by
`source.byteLength` (the correct side); this fix makes the constructor agree with
it, and the T2 door matrix now crosses a SOURCE dimension
({ArrayBuffer, full-span view, zero-offset partial view, offset view}) so the
agreement is proven across all four source kinds, not just ArrayBuffers.

## The decisions

**BR-01 -- base-within-buffer, checked before count is derived.** Root cause:
`avail = buffer.byteLength - base` could go negative because nothing checked
`base <= byteLength`; a derived `count = floor(avail/stride)` then went negative
and the final `count*stride > avail` fit check passed (both sides negative). Fix:
reject `base > buffer.byteLength` with `R_BAD_OFFSET` AFTER stride is derived and
BEFORE count is derived, plus a belt-and-braces post-derivation `count >= 0`
assertion (`R_BAD_COUNT`). `R_BUFFER_TOO_SMALL` still guards the explicit-count
fit. `byteOffset === byteLength` derives `count === 0` (a valid empty reader).

**BR-02 -- integer type codes only.** Root cause: `t >= 0 && t < 8` accepted
`2.5`/`"1"`; `TYPE_BYTES[t]` was then `undefined`, `maxEnd`/stride mis-derived,
and `type[i]` truncated in the `Uint8Array`, silently retyping the field and
sizing the record too small. Fix: `R_BAD_TYPE` now requires
`Number.isInteger(t) && t >= 0 && t < TYPE_COUNT`.

**BR-03 -- coherent byteOffset.** Root cause: `const base = opts.byteOffset || 0`
swallowed `NaN` and every other falsy value before the `Number.isInteger` guard
saw it. Fix: `const base = opts.byteOffset === undefined ? 0 : opts.byteOffset`,
so `NaN`/`Infinity`/`1.5`/`-1`/`false` all reach the guard and are refused with
`R_BAD_OFFSET`.

**BR-04 -- duplicate field names: REFUSE (decision).** Root cause: the name->id
`Map` was last-wins, so a repeated name silently shadowed the earlier field --
present in `fieldCount`, readable only by raw integer id, unreachable by name.
Decision: REFUSE with a NEW coded `R_DUPLICATE_FIELD` at the door. A name
collision is always a caller bug (a schema typo), and a silent shadow is the
worst possible outcome: the read-fidelity bijection line
(`field(schema[i].name) === i`) would be false and a caller would read the wrong
field with no error. Refusing at the door makes that bijection hold
UNCONDITIONALLY -- no duplicate-named schema can construct. The alternative
(document last-wins) was rejected: it turns a typo into silent data corruption,
which is precisely the failure mode this module exists to prevent.

**BR-05 -- coded `bytes()` door.** Root cause: an out-of-range `off+len` let the
`Uint8Array` constructor throw a raw `RangeError` with no `.code`; a negative
`len` likewise. Fix: a COLD guard on the D9 escape hatch -- a NEW `R_BAD_LENGTH`
for a non-integer/negative `len`, and `R_BUFFER_TOO_SMALL` when
`base + row*stride + off + len > buffer.byteLength`. This is not the numeric hot
path, so a cold guard here is in-contract.

**BR-06 -- coded cooperation doors.** Root cause: `fromBaked(null)` and a
fieldless `fromLBK1Shard({bytes,rowStride})` threw raw `TypeError` while
dereferencing the argument. Fix: validate the argument SHAPE before any deref --
`R_BAD_SOURCE` for a null/non-object baked or shard, `R_BAD_SCHEMA` for a
missing/empty `schema` (fromBaked) or `fields` (fromLBK1Shard).

## Consequences

- Every incoherent input throws a coded, greppable `R_*` at construction; no
  incoherent reader can be built. Law #2 holds.
- Two new codes join the R_* surface: `R_DUPLICATE_FIELD` and `R_BAD_LENGTH`
  (consumed by the S3 `.d.ts` `code` union).
- `checkCoherence` and the constructor agree on every door-matrix cell:
  `checkCoherence(src,opts) === null` IFF `new LiteBinaryReader(src,opts)` does
  not throw.
- The numeric read hot path is unchanged -- every fix is at the construction
  door or the `bytes()`/cooperation cold paths.
